# 试听渲染的缓存边界设计（只设计，不实现）

本文基于仓库当前调用链，给出“反复试听只重算改动部分”的可实现缓存方案，
明确不同缓存粒度在什么条件下仍能保证旧工程 PCM 字节级复现、什么条件下必须
让远处缓存失效，并用 `design/cache-boundary/probe` 中的可重复实验证否两个
朴素错误方案。本文不包含任何缓存实现，生产代码零改动。

- 探针代码：`design/cache-boundary/probe/`（独立 `package main`，仅复用生产导出 API）
- 证据输出：`design/cache-boundary/results/run-*.txt`
- 复现方式：仓库根目录执行 `go run ./design/cache-boundary/probe -exp all`

## 1. 当前调用链与两个“非局部效应”

一次试听渲染的真实调用链（`internal/service/renders.go:69` 进入）：

| 阶段 | 代码位置 | 性质 | 可否局部复用 |
|---|---|---|---|
| 源加载 + 完整性校验 | `storage/sources.go:58` `GetSource` 重读字节并重算 SHA-256，与 metadata 摘要不符即 `source_integrity_error` | 纯函数 + 安全闸门 | 校验必须每次先做；通过后的解码产物可缓存 |
| 解码/切片/重采样/声道映射 | `render/prepare.go:46-62`，调用 `audiocodec.DecodeWAV/SliceFrames/Resample/MapChannels` | 确定性纯变换 | 可按内容缓存（L1） |
| 摆放 + 等功率交叉淡化 | `render/mixer.go:19-48` `mixPrepared` | 帧写入依赖邻居 span 的淡化窗口 | 接点帧是两个 span 的共享产物，只能整体失效/重算（L2 共享块） |
| 全缓冲测量 + 全局峰值归一化 | `render/normalize.go:16-43` `normalizePeak`，`gain = target / 全局峰值`，单增益乘到**全部**样本并夹断 | 全局归约 + 全局逐样本乘法 | 最终 PCM 不能按块独立复用；pre-norm 样本与块峰值可以（L2） |
| 编码 + 回执 | `audiocodec/encode.go` `EncodePCM16`（PCM16 量化）、`render/receipt.go` `buildReceipt` | 确定性纯函数 | 量化后字节可在严格条件下复用（L3，可选优化） |

两个使“局部修改影响远处声音”的非局部效应：

1. **全局峰值归一化**：`normalize.go:19-23` 对整段 mix 求一个峰值并得到唯一增益，
   输出每个样本 = `preNorm[i] * gain`（再夹断）。任何一处 pre-norm 峰值变化都可能
   改变 `gain`，从而改变所有远处样本（实验 2 量化）。
2. **交叉淡化接点**：`mixer.go:32-45` 中，后一 span 的前 `CrossfadeFrames` 帧先把
   已有 mix 乘 `outgoing=cos` 再加权叠加 `incoming=sin`。接点窗口内每一帧都同时
   读取两个 span 的样本，改任何一个邻居，接点窗口全部帧变化（实验 1 量化）。

此外还有一个**位置效应**：`prepare.go:70-78` 的 `cursor` 是累加式的，改动 span 的
输出帧数或淡化帧数会平移其后所有 span 的 `OutputStartFrame`。因此“按输出位置键控”
的条目在帧长/淡化编辑后必须级联失效；而“按内容键控”的条目不受位置影响。

确定性前提已由实验 0 证实：同一输入两次 `render.Render` 输出 WAV 的 SHA-256 完全
相同，且探针参考实现（与 `mixPrepared`/`normalizePeak`/`EncodePCM16` 同公式）与生产
链路在 PCM16 量化后逐样本一致（28800 样本，0 不一致）。这是“旧工程 PCM 可复现”
的基线。

## 2. 缓存分层与缓存边界

建议把缓存放在**纯变换产物**上，而不是 HTTP/作业层；缓存是进程内、非持久化的试听
加速设施，与 `renders/<id>/` 下已提交的持久化产物（权威证据，不算缓存）分开。

### L1：prepared clip（解码/切片/重采样/声道映射产物）

- 键：`sha256(已验证源字节)` + 源帧区间 + 时间线采样率 + 输出声道数 + 变换代码版本。
- 对应 `prepare.go:46-62` 的输出 `mapped Clip`。该阶段不读取任何其它 span，是天然的
  内容寻址边界。源内容相同、参数相同即命中，与工程 ID、编辑序号、span 摆放位置无关。
- 命中后跳过的是成本最高的解码与重采样；这是“大工程音频块复用”的主力层。

### L2：pre-norm 固定网格块 + 块统计（核心正确性边界）

- 把归一化**之前**的 mix（`mixPrepared` 返回值、`normalize.go:17` 之前）按固定帧网格
  切块（探针用 2400 帧/块 = 50ms，一个 4800 帧淡化恰好跨 2 块）。每块存：
  - pre-norm 样本 `[]float32`；
  - 块峰值（线性幅度）；块 RMS（平方和与样本计数，供回执聚合，避免再扫全缓冲）。
- 块分两类，边界不同：
  - **内部块**：不与任何淡化窗口相交，仅依赖单个 span 的 L1 产物 + 该 span 增益，
    内容键 = L1 键 + gain。任一未编辑 span 的内部块永远可命中，与工程别处的编辑
    完全无关（实验 1 中 A、C 内部差异帧为 0）。
  - **接点块**：与某个 `CrossfadeFrames` 窗口相交，依赖相邻两个 span。键必须包含
    **两侧** span 的 L1 键与两个 gain、淡化帧数。任一邻居变化，该接点块整体重算，
    不能只重算“被编辑 span 自己覆盖的块”（实验 1 证否 H1）。
- 归一化改为两阶段，数学上与现有 `normalizePeak` 严格等价：
  1. 由各块峰值做一次 `max` 归约得到全局峰值（实验 2 打印了 12 个块的峰值表，
     只有编辑块峰值变化，汇总全局峰值 0.899991 → 0.950011）；
  2. 用同一 `gain=target/globalPeak` 对全部块做一次廉价的逐样本乘法 + 夹断
     （O(N) 次浮点乘，不含解码/重采样/淡化混合）。
- 因为 `normalizePeak` 不维护跨帧状态，分块归约与整缓冲计算结果逐位相同；实验 2 中
  两阶段重建结果与真实 `render.Render` 在 PCM16 量化后逐样本一致（不一致 = 0）。

### L3：量化后最终块（可选，仅优化，不承担正确性）

- 键 = L2 块键 + 本次全局增益 + 目标峰值 + 量化器版本。
- 仅当**全局增益与上次完全相同且该块 pre-norm 未变、夹断行为不变**时，才可直接复用
  最终 PCM 字节。满足条件时输出与旧工程字节级一致；不满足就退回 L2 重放缩放。
- L3 永远不能单独存在：把“最终 PCM 块”当作独立复用单位正是实验 2 证否的 H2。

### 失效半径汇总（编辑点 → 必须重算的最小集合）

| 编辑类型 | L1 | L2 接点块 | L2 内部块 | L3 / 最终 PCM |
|---|---|---|---|---|
| 改某 span 的 gain | 全命中 | 与该 span 相邻的接点块重算 | 该 span 内部块重算（键含 gain）；其它 span 全命中 | 全局增益可能变 → 全部最终块重放缩放 |
| 替换某源内容（新摘要） | 新内容 miss，旧条目保留 | 引用该源的 span 两侧接点块重算 | 仅引用该源的内部块重算 | 同上；峰值若被远处块持有且未被超过，增益可不变 |
| 改源帧区间 | 新区间键 miss | 相邻接点块重算 | 该 span 内部块重算；帧数变化还要按位置级联处理后续 span | 全部最终块重放缩放 |
| 改淡化帧数/增删 span | 已有内容键仍命中 | 新旧淡化窗口覆盖的接点块都重算 | 内容键不变的内部块仍命中；但输出位置平移，位置键条目级联失效 | 全部最终块重放缩放 |
| 改时间线采样率/声道/目标峰值 | L1 参数键全 miss | 全部重算 | 全部重算 | 全部重算 |
| 源字节损坏（摘要不符） | **禁止任何命中**，整单失败 | 同左 | 同左 | 同左 |

### 何时仍保证旧工程 PCM 字节级复现

同时满足以下三条时，缓存路径与全量路径输出字节相同（实验 0、实验 2 两阶段重建验证）：

1. 所有被引用源都通过 `GetSource` 的 SHA-256 校验，且 L1/L2 键中的摘要与之一致；
2. 重算集合覆盖“编辑块 ∪ 受影响接点块”，未重算块的内容键全部未变；
3. 全局增益由**当前**全部块峰值重新归约得到，缩放/夹断/PCM16 量化与
   `normalize.go`、`encode.go` 同公式同顺序（float32 运算顺序保持一致，禁止换累加序）。

### 何时必须让远处缓存失效

- **L2 pre-norm 层面：远处内部块永不因别处编辑而失效**——这是本方案能省算力的根本
  原因，实验 2 证明编辑后 A、C 与两个接点的 pre-norm 差异帧全部为 0。
- **L3/最终 PCM 层面：只要重新归约出的全局增益发生变化，所有最终块都必须重放缩放**，
  无论物理位置多远。实验 2 中 B 内部一个脉冲使 A、C 内部各约 99.9% 的最终样本改变。
- 增益不变时（编辑块新峰值 ≤ 原全局峰值，且持有原全局峰值的块未被改动，无新增夹断），
  L3 可直接命中并保持字节一致；这是“最终块缓存”唯一安全的快路径，需要用块峰值表
  判定，而不能假设成立。

## 3. 源字节损坏：完整性闸门先于缓存

现状 `storage/sources.go:72-75` 每次 `GetSource` 都重算载荷 SHA-256 并与 metadata
比对，不符返回稳定错误码 `source_integrity_error`。缓存设计必须维持并前置这个闸门：

1. **顺序强制**：一次试听在访问任何缓存条目之前，先对本次时间线引用的每个源执行
   `GetSource`；任一失败，整单渲染失败（沿用现有 `failRender` 终态），不读取、不写入、
   不回退任何缓存产物。
2. **键用已验证摘要，不用源 ID**：L1/L2 键中的源身份是“校验通过的 SHA-256 摘要”。
   源 ID 只是定位符；同 ID 字节被翻转后摘要改变，旧键在新请求中根本不可能被寻址到。
3. **禁止负缓存与旧成功回退**：校验失败不产生缓存条目，也不允许“上次成功的 WAV 还在，
   先返回它”。已提交的历史 render 产物属于持久化证据，不参与新请求的缓存命中。
4. 实验 3 同时显示：损坏一个 data 字节后 WAV 仍可被 `DecodeWAV` 正常解码（19200 帧），
   说明“能解码”不是可信依据，只有摘要比对能识别；并反证了“先查 ID 键缓存”的错误
   顺序会在损坏后继续交付旧输出。

## 4. 内存预算：与历史编辑次数解耦

- **内容寻址去重**：键是内容摘要而非 `(工程ID, 编辑序号)`。同一源内容被任意多工程、
  任意多版本引用，在缓存中只占一份。实验 4 中未改动的 A/C 源在 200 轮编辑里产生
  398 次内容命中，零新增内存。
- **字节预算 + LRU 淘汰**：缓存按条目字节数（`[]float32` 容量 ×4 等）记账，配置总
  预算；超预算按最近最少使用淘汰。淘汰的只是可由源字节重建的派生物，不影响正确性，
  只影响下一次命中率。实验 4：预算 1,228,800 字节下，200 轮编辑后存活条目稳定在
  16–17 个、占用恒定 1,228,800 字节（第 50 轮起不再增长），而朴素只增缓存达到
  600 条 / 30,720,000 字节。
- **无界增长来源被显式封死**：失败渲染不写缓存（无负缓存）；LRU 不保留历史版本链；
  内存上界是配置常数，与累计编辑次数无关。
- 大对象防护沿用现有 `MaxSourceBytes`/`MaxOutputFrames`（`service/types.go:28-34`），
  单条目尺寸天然有界，预算核算不会溢出。

## 5. 可解释性：工程、试听、回执共同解释一次命中

一次命中的依据必须能由三方材料独立复核：

1. **工程（已持久化输入）**：时间线 JSON（span 的源 ID、帧区间、gain、淡化帧数）与
   源 metadata 的摘要，是缓存键输入的权威来源。
2. **试听（缓存决策记录，建议新增的非持久化审计结构）**：每次试听输出一份决策清单，
   逐块列出 `block / 键摘要 / hit|miss|recomputed / 失效原因（接点耦合|摘要变更|增益变更|未校验）/
   重算的块峰值 / 归约出的全局增益`。实验 2 的块峰值表就是该清单的原型。
3. **回执（持久化输出证据）**：现有 `RenderReceipt` 已含每个 span 的 `SourceDigest`、
   摆放、gain、`Normalization.BeforePeakDBFS/AppliedGainDB/OutputPeakDBFS` 与输出摘要
   （`domain/entities.go:87-103`）。建议扩展一个 `cache` 段（schema_version 递增）：
   记录各层键前缀、命中/重算块计数、全局增益来自哪些块峰值的归约、以及引用源摘要列表。
   回执仍只在输出原子提交后写入（`storage/renders.go:34`），语义不变。

复核逻辑：用工程里的源摘要 + span 参数按第 2 节公式重算键，应与试听决策清单中的键
一致；清单中的块峰值 `max` 必须等于回执 `BeforePeakDBFS`，归约增益必须等于
`AppliedGainDB`；输出 SHA-256 必须等于回执 `Output.Digest`。三者闭合才算一次可解释的
命中。

## 6. 被证否的错误方案（实验对应关系）

| 错误方案 | 证否实验 | 观测到的反证 |
|---|---|---|
| H1：只让“被编辑 span 自己覆盖的块”失效，邻居块沿用旧最终 PCM | 实验 1 | B 整体取反（峰值/RMS 不变、全局增益不变）后，两个接点 J1/J2 各有 4799/4798 帧变化；H1 拼装与真实重渲染在块 2、3、8、9 上不一致，接点处遗留陈旧淡化值；而 A、C 内部差异帧为 0，说明正确失效半径是“编辑块 ∪ 接点块”而非整段远处 |
| H2：按块缓存最终 PCM，编辑后只重算改动块，其余块直接命中 | 实验 2 | B 内部一个 0.95 脉冲使全局增益 −0.0848 dB → −0.5546 dB；pre-norm 远处与接点差异帧全 0，但最终 PCM 远处 A/C 内部各 4796/4792 帧改变；H2 拼装在 11/12 块上与真实输出不同，而其峰值指标与真实输出完全相同（0.891263），峰值级冒烟校验漏检 |
| H3：缓存键只用源 ID 与渲染参数，损坏后仍可命中旧成功 | 实验 3 | 翻转一个源数据字节后 `GetSource` 稳定返回 `source_integrity_error`，且损坏字节仍可解码；模拟 ID 键缓存时损坏完全不可见、旧 WAV 照常命中。正确顺序是校验先于查缓存、键含已验证摘要、失败即整单失败 |
| 朴素只增缓存（每编辑一轮新增条目、不淘汰） | 实验 4 | 200 轮后 600 条 / 30 MB 线性无界；内容寻址 + 字节预算 LRU 恒定 16–17 条 / 1.2 MB，且未改动内容 398 次命中 |

实验 0 是所有结论的可信基线：生产链路确定性（两次渲染 SHA-256 相同）与探针参考实现
的等价性（量化后 28800/28800 样本一致）。

## 7. 复现步骤

```bash
# 全量证据（退出码 0 即全部断言通过）
go run ./design/cache-boundary/probe -exp all

# 单独复现
go run ./design/cache-boundary/probe -exp exp0   # 确定性与探针基准
go run ./design/cache-boundary/probe -exp exp1   # 跨块接点：证否 H1
go run ./design/cache-boundary/probe -exp exp2   # 远处更大峰值：证否 H2，验证两阶段重建
go run ./design/cache-boundary/probe -exp exp3   # 损坏闸门：证否 H3
go run ./design/cache-boundary/probe -exp exp4   # 内存预算有界性
```

最近一次运行的完整输出保存在 `design/cache-boundary/results/`。探针不监听端口、
不写工程数据目录（实验 3 使用独立临时目录并清理），不修改 `internal/` 与 `cmd/`
下任何生产代码；现有三个生产冒烟检查在新增探针后仍全部通过。

## 8. 落地时对现有代码的最小触及面（供后续实现阶段参考，本轮不做）

- `render/prepare.go`：把 `mapped Clip` 的产生抽成可被 L1 包装的纯函数入口；
- `render/mixer.go`：切块产出 pre-norm 块与块峰值/RMS，接点块按双邻居建键；
- `render/normalize.go`：保留同一增益公式，输入改为块峰值归约，缩放遍历改为按块；
- `service/renders.go`：在 `render.Render` 前集中完成全部源 `GetSource` 校验，再传入
  缓存组件；失败路径维持 `failRender`；
- `domain/entities.go`：回执新增 `cache` 段并提升 `SchemaVersion`；
- 新增缓存组件自身实现预算 LRU 与决策清单，不引入持久化与外部依赖。
